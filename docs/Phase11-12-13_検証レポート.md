# 第1部：Phase13 実装報告

## 1. 実装概要

- `amazon_sales_lines` を基準テーブルに、`sales_state = confirmed` のみ対象
- `amazon_fee_events` を `order_id` 単位で集約し、手数料を付与
- 日次・月次・SKU別・ASIN別の集計を返す `/api/amazon-sales-summary`
- Phase13 検証 API（`/api/amazon-phase13-verify`）を追加
- `/amazon-sales` に「集計サマリ表示（Phase13）」ボタンを追加

## 2. 変更ファイル一覧

|------|------|

| ドキュメント | `docs/Phase13_売上集計API_実装概要.md` |

## 3. 追加した集計API一覧

| API | メソッド | 役割 |
|-----|----------|------|
| `/api/amazon-sales-summary` | GET | confirmed 売上を期間別・SKU別・ASIN別に集計 |
| `/api/amazon-phase13-verify` | GET | 集計対象件数・fee 反映・サンプルを検証 |

**クエリパラメータ（amazon-sales-summary）**: `from`, `to`（YYYY-MM-DD）

## 4. 集計対象の基準

| 項目 | 内容 |
|------|------|
| 対象条件 | `sales_state = confirmed` のみ |
| 除外 | pending_price, canceled, other_excluded |
| 日付基準列 | `order_date`（売上日） |
| line_count | 売上行件数（1注文1商品=1行） |
| order_count | ユニーク order_id 数 |

## 5. 集計項目一覧

| 項目 | 説明 |
|------|------|
| order_count | ユニーク注文数 |
| line_count | 売上行件数 |
| units_sold | 販売数量の合計 |
| sales_amount_yen | 売上金額の合計 |
| fee_amount_yen | 手数料合計（order_id 単位集約） |
| sales_after_fee_yen | 売上−手数料 |

## 6. fee_amount_aggregated の反映方法

1. `amazon_fee_events` を `order_id` 単位で SUM して fee マップを作成
2. **日次・月次・合計**: 期間内の order_id の fee をそのまま合計（重複なし）
3. **SKU別・ASIN別**: 同一 order 内の売上比率で fee を按分
4. 売上行を直接 JOIN して増やさない

## 7. 未対応として残したもの

- 原価を含めた粗利
- 会計帳簿レベルの厳密一致
- FBM 在庫の完全対応
- DebtRecoveryEventList
- ダッシュボードの最終 UI

## 8. 次フェーズの推奨

- 原価の取得手段が固まっていれば粗利対応を検討
- 在庫・出荷の FBM 強化が必要なら FBM 対応を検討

## 5. Phase12 改善提案

1. **AdjustmentType マッチ拡張**  
   `PostageBilling_VAT` 等を含めるため、完全一致ではなく `startsWith('PostageBilling')` での判定を検討。

   別テーブルや集計単位での扱いを検討。
